# DIO Fusion Wave 1

Fusion Wave 1 begins only after Incarnation earns `READY_FOR_FUSION`.

It does not merge specialist Git histories or turn every organ into one process. It creates a canonical semantic membrane through which specialist systems contribute evidence, observations, challenges, requirements, authority records, capability requests, decisions and receipts to Governed Case v2.

## Canonical assertion

Every fused contribution uses `dio.fusion.assertion.v1` and binds:

- issuer system and role;
- subject kind/reference;
- typed payload;
- epistemic state, evidence authority grade, trust and freshness;
- lineage into a Governed Case and source references;
- Valinor kernel authority boundary;
- human/release boundary;
- deterministic fingerprint and assertion ID.

## Authority laws

1. Only Valinor may emit `kernel_authorized=true`.
2. Only an explicit human authority receipt may emit `external_release_authorized=true`.
3. A Seraph/Metatron challenge never carries kernel authority.
4. A capability request remains a proposed Governed Case action and therefore remains blocked unless its ordinary gates allow it.
5. External capability requests automatically include the `external_release` gate.
6. Fusion assertions do not replace Governed Case; they project into it.

## Mandatory participants

The binding registry covers every system marked mandatory by `config/dio_fusion_registry.json`, including DIO Core, Vesper, Sophia, Valinor, BEAST, Metatron/Seraph, ARDA semantics, Phoenix, Evidex, VAMP, HOMS, Outlook Triage, Microsoft Graph/Outlook/OneDrive, NicheFoundry, Document Studio, Lingua, Format Core, Legalis, Market Command, Commerce/AutoRelease, the DIO Product Platform and the DIO Workflows public claim surface.

Outlook/Graph side effects remain capability-bound. HOMS/eFundi publication remains educator/institution-bound. Phoenix capital deployment remains locked behind its independent profitability/promotion gates. Public sites remain governed surfaces rather than runtime authorities.

## Command

After pulling the Fusion Wave 1 head:

```bash
cd /home/byron/DIO
./dio fusion1
```

The command requires an existing `READY_FOR_FUSION` Incarnation receipt, runs the Fusion Wave 1 invariant tests and writes:

```text
/home/byron/DIO/receipts/fusion-wave1-latest.json
```

Expected state:

```text
FUSION_WAVE1_READY
```

That state means the shared contracts and mandatory semantic bindings are ready. It does not mean every specialist executor has completed live runtime acceptance.
