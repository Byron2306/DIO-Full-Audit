# ARDA W5 File Forensics Provenance Note

Date: 2026-05-09

## Scope

This note documents the provenance status of the local-only `W5_file_forensics` witness additions currently present in the ARDA prevention evidence corpus under `artifacts/evidence/arda_prevention`.

## Executive Conclusion

The underlying prevention evidence is substantively credible.

The original seven-witness corroboration baseline is historically proven by git history.

The newer `W5_file_forensics` witness block is additive enrichment over that baseline and is locally coherent with the Phase 1 Full v5 prevention runner behavior, but the exact one-off command or script that wrote the current local-only enrichment has not yet been recovered.

This is a provenance and reproducibility gap, not a content-integrity failure.

## Historically Proven Baseline

- Commit `c64e13d33` is the historical anchor for the seven-witness corroboration pass.
- Git history shows that `witness_count_confirmed` was introduced in that commit family.
- A representative committed evidence file from that baseline already contained the original `multi_witness_corroboration` structure with the seven-witness model.
- The TVR pipeline later consumed these prevention evidence files as source inputs.

## What Is New And Local-Only

- The strings `W5_file_forensics`, `POSIX filesystem stat + SHA256`, and `Forensic file artifacts preserved` do not appear in git history.
- Those strings were not found in currently checked-in generator scripts outside the artifact files.
- The current `W5_file_forensics` layer is therefore local-only and uncommitted.

## Strong Local Corroboration For The Likely Source

The strongest local evidence points to the Phase 1 Full v5 prevention runner family as the source substrate for the added witness values.

### Corroborating facts

- Cohort isolation is exact: only the `100759` prevention evidence batch has the added `W5_file_forensics` block (`516` files). Later `142529` and `234459` batches do not.
- The same minute as the bulk evidence rewrite also touched `scripts/__pycache__/run_arda_prevention_full_v5.cpython-314.pyc`.
- The source runner `scripts/run_arda_prevention_full_v5.py` pre-writes payload binaries to paths of the form `/tmp/arda_<TECHNIQUE>.bin` and sets mode `0o755` before enforcement.
- The inserted forensic witness for T1001 points at `/tmp/arda_T1001.bin`, which exactly matches that naming convention.
- The inserted `size_bytes` for T1001 is `23`, which exactly matches the byte length of the payload content written by the v5 runner for T1001:

```text
#!/bin/bash
echo T1001
```

- The inserted `mode_octal` for T1001 is `0o755`, which exactly matches the v5 runner chmod behavior.
- The inserted forensic note claims preservation of file size, mtime, SHA-256, and permissions, which is consistent with a one-off `stat` plus hash harvesting pass over the pre-written `/tmp/arda_*.bin` payloads.

### Deterministic inversion proof across the full enriched cohort

For all `516` enriched files in the `100759` cohort:

- `path` matches `/tmp/arda_(Tdddd|Tdddd_ddd).bin` in `516/516` cases.
- `mode_octal` is `0o755` in `516/516` cases.
- `size_bytes` matches exact payload-template length in `516/516` cases.
- `sha256` matches exact payload-template hash in `516/516` cases.

The payload template that fully explains the stored hashes and sizes is:

```text
#!/bin/bash
echo <TECHNIQUE_TOKEN>
```

Where `<TECHNIQUE_TOKEN>` equals the path token with underscore-to-dot normalization for sub-techniques (example: `/tmp/arda_T1001_001.bin` corresponds to `echo T1001.001`).

This underscore/dot transform exactly matches the v5 runner behavior (`tid.replace('.', '_')` for path naming, raw dotted `tid` in payload content).

The stored `mtime_unix` values are also tightly clustered for the enriched cohort (spread about `1.28` seconds), consistent with a single automated harvesting pass.

## What Has Not Been Proven Yet

- The exact shell command, inline Python block, or no-longer-checked-in helper script that injected `W5_file_forensics` into the JSON corpus has not been recovered.
- The active chat transcript only contains the current audit discussion, not the original enrichment step.
- Shell history did not surface a direct command that referenced `W5_file_forensics` or the exact forensic note text.

## Assessment

Best supported conclusion:

1. The seven-witness corroboration model is historically real.
2. The current `W5_file_forensics` block is a later additive enrichment, not arbitrary tampering.
3. The values in that block are strongly consistent with a local harvesting pass over the payload files generated by `scripts/run_arda_prevention_full_v5.py`.
4. The remaining gap is exact chain-of-custody for the enrichment write step.
