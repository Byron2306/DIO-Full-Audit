## Objective

Make intake, scope sufficiency and quote presentation deterministic over governed product truth rather than conversational inference.

Phase 2 freezes four shared contract families:

1. `IntakeRequirement`
2. `ScopeReceipt`
3. `QuoteRequest`
4. `QuoteResult` with canonical `Quote`

The customer-facing presence layer may render these contracts conversationally. It may not recreate required inputs, scope or price from chat memory.

## Architecture

```text
68-product commercial pricing registry
        ↓
exact canonical product resolution
        ↓
IntakeRequirement
        ↓
typed supplied facts + evidence refs
        ↓
ScopeReceipt
   INCOMPLETE / SUFFICIENT
        ↓
QuoteRequest
        ↓
commercial tier reference + quote authority policy
        ↓
ALLOW_PRESENTATION / NEEDS_YOU
        ↓
canonical Quote only when policy permits
```

`presence_core/intake_scope_quote.py` is the shared Journey Spine seam. It consumes the existing 68-product commercial registry instead of introducing 68 product-specific intake or quote implementations.

## Frozen intake contract

Every commercial product resolves to a declarative intake requirement derived from its existing commercial profile.

The Phase 2 minimum required fields are:

- `requested_outcome`
- `buyer_class`
- `scope_quantity`

The selected product declares the semantic unit for `scope_quantity` through its existing `primary_scope_unit`. Existing `secondary_scope_units` become optional typed scope dimensions.

Each input declares its allowed source and `inference_allowed: false`.

Unknown input fields are rejected. Free-form conversational guesses therefore cannot silently become scope truth.

## Scope sufficiency

A `ScopeReceipt` is `SUFFICIENT` only when:

- the requested outcome is non-empty;
- the buyer class is explicitly supported by the selected product;
- the scope quantity is a positive integer.

Otherwise the receipt is `INCOMPLETE` and identifies exactly which required facts are missing or invalid.

An incomplete receipt leaves the Journey Case in `INTAKE_OPEN` and cannot create a quote request.

A sufficient receipt is hash-bound and advances the Journey Case to `SCOPE_ASSESSED`.

## Quote contract

A `QuoteRequest` is derived only from:

- canonical case identity;
- canonical product identity;
- buyer class;
- hash-bound sufficient scope receipt;
- declared scope unit and quantity;
- existing pricing model;
- existing quote-authority mode.

The price reference is selected from the existing `commercial_tiers` generated by `products/commercial_pricing_registry.py`.

No customer message text is parsed for a price and no scope multiplication rule is invented by Phase 2.

### Bounded estimate

Where the existing commercial profile declares `bounded_estimate`, and the governed tier reference amount remains at or below the existing autonomous ceiling, the result is:

`ALLOW_PRESENTATION`

The canonical quote records:

- `pricing_truth: GOVERNED_REFERENCE_POINT`;
- `commercial_validation: UNPROVED`;
- `customers_will_pay: UNPROVED`;
- `presentation_authority: true`;
- `invoice_issue_authority: false`;
- `external_send_authority: false`;
- `payment_collection_authority: false`;
- `fulfilment_authority_created: false`;
- `release_authority_created: false`;
- `authority_created: false`.

Quote presentation therefore does not imply invoice authority, settlement truth, fulfilment authority or release authority.

### Operator review

Where the existing profile declares `operator_review`, Phase 2 exposes the governed pricing reference internally but returns:

`NEEDS_YOU`

No customer-presentable canonical quote is created by that decision. The pricing reference remains `customer_presentable: false`.
