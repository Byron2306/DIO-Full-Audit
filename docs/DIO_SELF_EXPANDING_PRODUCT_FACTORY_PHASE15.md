# DIO Phase 15 — Self-expanding Product Factory

Phase 15 proves that DIO can manufacture a new governed product incarnation from a closed declarative specification without hand-editing its generated profiles, manifest, capability bindings, validation contract, portfolio registration, or runtime wiring.

## Factory Contract

A factory specification declares product identity, source type, six-axis composition inputs, required capabilities, evidence vocabulary, output sections, maturity ceiling, release boundary, and a controlled reference case. The schema permits only internal products at `internal_proof` with external release fixed to `REFUSE`.

## Materialisation

The factory creates a sandbox incarnation containing four source-bound product-specific profiles, bindings to the existing read-only connector and internal-proof commercial profile, a canonical manifest, exact-scope generic executor capability, proof providers, a generated validation contract, a GoldenEye registration projection, and a factory receipt. It updates sandbox copies of the existing profile index and capability catalog; it does not bypass them.

## Execution

The ordinary Product Compiler v1 compiles the generated manifest. The generic generated-product runtime evaluates required evidence types, integrity, currency, human authority, requested effects, and release state. It emits deterministic JSON, HTML, DOCX, PDF, proof-manifest and execution-receipt artifacts.

## Self-expansion Boundary

Generation never creates authority, maturity, market validation, customer acceptance, revenue, compliance, certification, permission, external filing, external delivery, or release. A malformed, path-escaping, maturity-promoting, capability-inventing, or externally releasing specification is refused.

## Reference Incarnation

The reference specification generates DIO IncidentReadinessProof. This product did not exist in the Phase 14 canonical product registry. It is produced entirely from the declarative factory specification, compiled in an isolated materialised repository, exercised twice for determinism, tampered adversarially, and projected into GoldenEye without changing live-world truth.

## Final Acceptance

Phase 15 passes only when the generated product is registry-bound, compiler-valid, executable, deterministic, hash-verifiable, adversarially guarded, human-gated, release-refusing, and all Phase 14 regressions remain green.
