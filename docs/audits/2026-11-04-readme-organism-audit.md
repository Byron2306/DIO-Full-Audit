## Additional technical risks not repaired by documentation

1. **Environment-specific paths.** Sonoris and Dicere adapters reference absolute paths under `/data/byron` and `/home/byron`; fresh clones cannot reproduce those stages without an explicit runtime install/manifest. Provide configurable runtime-root bindings and preflight errors. The README accurately states this dependency.
2. **Inconsistent maturity registries.** `config/product_class_routes.json` describes multiple profile-extension products as lacking direct execution engines, while newer explicit customer routes may produce bounded products through different handlers. These are different layers, but the naming invites false equivalence. Unify a typed matrix per offer: canonical identity, route kind, native executor, effect scope, domain review and proof provenance.
3. **Artifact representativeness.** Several product/Studio pairs share identical selected primary artifacts; the proof portfolio selection is deterministic, not independent scoring. Distinct Studio usability and revisions need separate evidence.
4. **Substantive quality gaps.** HOMS requires educator review and assessment quote/reasoning repair; Afrikaans requires proficient review; creative media rights, visual correctness and professional sonic sign-off remain open. Maintain blocking criteria rather than renaming them “ready.”
5. **Portable evidence and CI.** Selected bundles are versioned, but many local acceptance receipts are not reproducible from the GitHub clone alone. Add a manifest of public/portable versus local-only proofs and re-run a named CI matrix on the exact candidate commit.
6. **Governance enforcement claims.** A normative Valinor/Arda/Seraph chain must not be described as actively enforcing on all deployments without exact runtime attestation. The README distinguishes doctrine from live activation.
7. **Cross-organ QA.** Integrated video proof demonstrates media assembly, not customer-approved brief compliance, phoneme alignment, source claim correctness, model rights, or repeatable cost/latency. Add inter-organ contracts and independent end-to-end test fixtures.
