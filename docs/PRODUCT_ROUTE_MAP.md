# Product Route Map

## Core Route Philosophy

The suite should not ask clients to learn five tools.

It should accept ordinary inputs:

- Email threads.
- Attachments.
- ZIP files.
- Google Drive folders.
- Forms.
- Manual uploads.

Then route them into product jobs.

## First Routes

### Outlook to Evidex

Trigger examples:

- "grant report"
- "compliance"
- "evidence pack"
- "proof of delivery"
- "M&E"
- "KPI"
- "funder"
- "audit"

Flow:

```text
Email/thread/attachments
-> triage summary
-> evidence candidate list
-> Evidex job
-> evidence table and pack
-> delivery draft
```

### Outlook to NicheFoundry

Trigger examples:

- "campaign"
- "content"
- "landing page"
- "lead magnet"
- "script"

- "social post"
- "market research"


```text

```

## Route Safety

All routes must preserve:

- Human approval.
- Source evidence.
- Privacy minimization.
- Audit logs.
- No autonomous sending.
- No fabricated facts.
