## Validated baseline findings

1. **The universal shared finish is an inventory wrapper, not real Format Core execution.** `presence_core/shared_production_finish.py::finish_fulfilment_for_review` builds raw HTML containing artifact IDs, filenames and hashes plus an inventory manifest. It does not call the registry's advertised `adapters/format_core/renderer.py::render_semantic_asset`, parse source bytes, or verify source hashes. An isolated probe patched the real renderer to raise if called and supplied a nonexistent `report.md` with a fabricated 64-character digest: both organ steps reported PASS and the renderer call count was zero. This is a validated baseline defect, not a claim that all native routes lack real formatting. `presence_core/fulfilment_contract.py::dispatch_fulfilment` invokes that wrapper only on the Journey dispatch path; the prepared 53 harness has its own route calls.

2. **Real reusable semantic finishing already works.** An isolated local probe called `register_product_source` → `semantic_content_from_lingua_object` → `render_semantic_asset` and produced DOCX and HTML with two semantic strings, zero missing strings, and passing QA. Document Studio already calls that renderer. The prepared HOMS Exam route already gains real DOCX+HTML through `professional_evidence_customer_surface_compat::_homs_exam_surface_wrapper`. Extend those content paths; do not count another index page as improving the customer's report.

3. **Import-time patches determine effective execution.** `professional_evidence_prepared_executor.py` installs final, red13, final3, Sophia diagnostic and customer-surface compatibility layers before binding `_route_execute`. Calling the base executor directly can bypass repaired VAMP invocation, customer Evidex identity, HOMS rendering, Sophia tutor and campaign composition. The machine crosswalk identifies code-connected capabilities, not fresh proof that every entrypoint uses the same provider. Consolidating these repairs into explicit adapters would make execution auditable.

4. **Market and campaign products lose the customer question before production.** The effective `professional_evidence_final_compat::_run_market_radar_current` ignores `packet` and runs a global `MarketSensoriumCycle(ROOT)` refresh. `professional_evidence_executor::_run_opportunity_with_radar` records the cycle receipt, then `professional_evidence_native::run_opportunity_foundry` returns three fixed hypotheses and a fixed R5,000 portfolio limit. No market output is consumed in ranking. `run_offer_lab` similarly fixes its buyer, offer and price tests and merely appends customer constraints. The effective campaign `final3::_run_campaign_lab_v3` calls `red13::_campaign_inputs`, which supplies fixed Campaign Lab self-promotion while the packet enters only through a proof bridge. Media execution/anti-clone/visual diversity can be real while the campaign fails the actual customer job.

5. **Several products have honest but narrow substance.** HOMS Exam constructs one fixed Grade 11 History 150-mark, two-hour paper and generic memo after checking two strings. HOMS Curriculum uses keyword tags, not outcome-to-unit/assessment reconciliation. The learning-pack builder explicitly supports only Grade 10 Physical Sciences, Term 3, motion in one dimension, English. Accessible Publish emits a placeholder figure and predetermined issue records. These outputs can be useful bounded examples, but a general product needs source-driven content and wider scope acceptance.

6. **Eleven native extensions perform real Lingua registration and BEAST mechanics, but mostly render short source summaries/checklists.** `_execute_fixture` creates meaning units, renders buyer HTML, and invokes the harvested BEAST quality cascade. `build_semantic_rows` emits requirement supplied/missing labels, venture facts/questions, generic correspondence position, or planned channels. FundingFinder does not retrieve funding opportunities; Launch Studio does not build launch assets; Contract Desk does not extract clauses; Report & Pitch Studio does not manufacture a deck. Better domain paths already exist for several of these jobs. Four Studio extensions use a separate, richer closure/customer-delivery lane and must not be flattened into the eleven-extension finding.

7. **The nine high-risk products deliberately invoke no domain engine.** `unpromoted_high_risk_profile::validate_no_engine_boundary` requires `engine_assigned=false`, `engine_invoked=false`, no suggested engine and no execution proof. Their shared evidence review may be useful, but it is not a cyber scan, model validation, incident investigation or operating-control drift detector. Improve source/evidence presentation within this boundary; new specialist functionality requires its own implementation and proof.

8. **Finance and quality adapter names require precise claims.** Sophia finance labels/hashes assumptions; VAMP finance constructs planned milestones; Evidex finance maps explicit requirement IDs to evidence IDs and explicitly records that the full engine was not invoked. BEAST ProductGrade invokes language inventory, HTML syntax and JavaScript syntax checks; optional skipped tools can coexist with mechanical PASS. None establishes financial correctness, source truth, rendered visual quality or specialist review.

9. **The accreditation projection conflates criteria with evidence.** `professional_evidence_native::run_accreditation` turns every evidence-register row into a mandatory criterion and an evidence record supporting that same criterion, asserting current freshness and trusted-for-review state. A held release gate does not make that a valid external-standard coverage assessment. Preserve actual framework criteria independently and assess evidence against those criterion IDs; missing metadata must stay unknown.

## Prioritised concrete reuse changes

1. **P0: Fix customer content dataflow before polishing.** Give market/campaign/opportunity/offer routes explicit approved customer inputs: segment, geography, horizon, buyer, problem, offer, claims, source references, CTA, channel and budget. Derive these from captured customer bytes with a field-to-source map, refusing or labelling missing fields. Make selected observations feed ranking and make campaign source facts feed existing `build_family`. Validate with a genuinely changed buyer/topic/budget, not only an appended stale or adversarial note.
2. **P0: Prove the finisher executes the advertised provider over real bytes.** Introduce typed route semantic output or an explicit content adapter, verify held source bytes/hashes, register source units and call real Format Core for requested channels. Retain the inventory manifest as custody evidence with truthful naming. A missing/tampered file must fail; changing substantive content must change rendered content. Use product-specific tables and status sections, not a universal ID/hash page.
3. **P1: Reuse existing semantic/rendering and evidence presentation in the eleven extensions and review families.** Feed actual requirement/evidence/issue structures into cohesive sections, then render DOCX/PDF/HTML or PPTX as requested. Reuse `obligationfamily/quality_presentation.py` patterns after schema adaptation. Expand generic extensions into the already existing finance, ContractProof, article, correspondence and campaign providers only when real customer input contracts are satisfied.
4. **P1: Add substance to assessment and learning while keeping educator authority.** Use actual completed assessment outputs in harvested `ModerationAgent.batch_moderate` for cohort outliers and `LearningAgent` for common errors. Preserve the source rubric and findings. Parameterise exam scope and bind questions/memo to supplied source spans; make curriculum explicit outcome coverage. Keep the illustrated motion lesson as a supported topic until other topics pass equivalent checks.
5. **P1: Reuse precise finance helpers, without broad finance-engine claims.** Put real dated requirement IDs, evidence IDs, amounts, periods and assumptions into finance readiness artifacts. Join gap map, source figures, objectives and assumptions in the buyer report, adding independent arithmetic/source reconciliation. FundingFinder needs a retrieved, dated shortlist before it can claim opportunity screening; the generic metamorphic Funding Proposal wrapper explicitly does not yet prove content transformation and is not a drop-in fix.
6. **P2: Use BEAST/Lingua where they change delivered substance.** Retain real source-unit custody, exact approved translation reuse and stale translation invalidation. Run BEAST mechanics on actual selected deliverables, report skips clearly, and add browser/rendered visual inspection separately. Art-direction/visual-QA metadata should accompany, not replace, actual layout/readability/accessibility checks.
7. **P2: Consolidate compatibility layers and clarify execution evidence.** Make effective providers explicit at dispatch; preserve provider source digests, consumed customer source hashes, emitted semantic hashes and QA receipts. Distinguish route-family execution, named-product artifacts and specialist-domain validation in results.

## Unsafe or unsupported shortcuts rejected

- The harvested HOMS `backend/server.py::generate_exam_sources` prompts an LLM for “authentic” primary sources using approximate historical content. Its existence is not a safe source retrieval capability. Require supplied or independently verified historical sources before question construction.
- Harvested `ModerationAgent.detect_plagiarism` compares shared rubric satisfaction booleans; it is not textual plagiarism detection and should not be presented as such.
- `products/funding_proposal_studio.py` runs `build_reference_intent` and declares `content_transform_dataflow_proved=false`; merely inserting it would prove a reference composition, not customer funding material transformation.
- Hivenance commercial observation and Sensorium episode adapters supply evidence envelopes/custody; they do not by themselves run research, prove market demand or improve customer narrative.
- Source existence/hashes in `shared_capability_registry.py`, `ROUTE_COMPOSITIONS` labels, HTML syntax and human gates cannot establish that a provider consumed customer content.

Canonical names were extracted with Python AST from `ARCHETYPE_PRODUCTS`, compared with the 53 professional route keys, and reconciled to eleven native plus four Studio extension names. Every capability source and symbol was checked to exist and recorded with SHA-256 and line number. The two isolated probes used temporary directories and local Python only: semantic source→DOCX/HTML passed completeness checks; shared finish emitted PASS without the advertised renderer or source bytes. During the initial review, no external network, live state mutation, full portfolio run, or production code change was performed. The authorised follow-up changed only the native accreditation projection/function and added its regression file, then ran the three local accreditation journeys documented in the addendum.

Runtime availability and complete specialist quality of the inventoried providers are not inferred from source. Root-owned portfolio reruns and the extension agent own current execution results. Browser layout, accessibility, mathematical correctness, citation authenticity, source applicability and customer task completeness still require direct artifact examination or dedicated validation. The baseline findings must be rechecked against final implementation hashes before claiming repaired integration.
