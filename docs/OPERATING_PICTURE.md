# KnowEdge AutoRelease Operating Picture

Updated: 2026-08-07

## The Big Idea

KnowEdge AutoRelease is not one app.

It is a release spine for small AI-assisted service products:

```text
ordinary client input
-> route into the right product layer
-> produce a reviewable pack
-> require human approval
-> generate a campaign/proof asset
-> sell the next pilot
```

The strategic unlock is that every product can share the same proof-and-release loop while serving a different niche.

## Core Spine

```text
Triage / form / upload
-> job envelope
-> evidence or work packet
-> deterministic adapter
-> approval receipt
-> deliverable folder
-> NicheFoundry campaign/video
-> landing page / outreach / pilot offer
```

The spine matters more than any single product. A product can be weak and still teach the route. A strong product can then reuse the same route and sell faster.

## Product Roles

|---|---|---|

## Build Sequence

### Now

```text
1. Send 5-10 Outlook-first Evidex prospect messages.
2. Pull replies through Outlook Triage.
3. Route real replies into AutoRelease.
4. Use Google/Drive/paygate only after the lead is qualified.
5. Generate one reviewed pilot pack.
6. Ask for payment, testimonial, or referral.
```

### Next

```text
1. Send Evidex and HOMS first-prospect messages.
2. Promote VAMP through the same preview route.
3. Turn Outlook Triage results into an operator queue.
4. Add a service dashboard: leads, jobs, approvals, deliveries, payments.
```

### Later

```text
1. Add Google Drive intake.
2. Add Stripe or local payment alternatives.
3. Add email/webhook delivery.
4. Add CRM tracking.
5. Add customer-specific templates.
```

## What Not To Build Yet

Avoid:

- full SaaS login systems,
- complex subscription billing,
- automatic client emailing,
- automatic publication,
- heavy multi-tenant architecture,
- unpaid custom integrations.

The current winning move is service-first:

```text
manual fulfilment where needed
automation where proven
receipts everywhere
sell the outcome, not the machinery
```

## Definition Of Progress

This project is working when:

```text
one stranger or loose contact sends a real sample
-> the system routes it
-> the adapter produces a useful pack
-> the operator reviews it
-> the client understands the value
-> money changes hands
```

Nothing else is the scoreboard yet.

The controlled Evidex loop proves the machine can complete the path. The next scoreboard is no longer more internal proof; it is one controlled outside pilot with fake/redacted evidence and a real payment/testimonial/referral decision.
